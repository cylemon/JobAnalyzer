# 该文档是本项目的使用示例描述文档

> 本版（2026-10-04）按新界面重写：四个页面 —— 综合看板 / 岗位信息 / 个人信息 / 系统设置。
> 需求见 02 文档，数据模型与算法见 03 文档。

## 1. 使用示例描述 (Usage Example & User Journey)

### 场景一：把「我会什么」录进来（个人信息）

用户打开「个人信息」，做三件事，顺序无所谓但三件都要做：

1. **专业知识**：把会用的技术栈逐个录进去（`Python / FastAPI`、`Kubernetes`…），顺手标个熟练度。
   知识是唯一能被本地精确比对的资产——录得越全，后面的分数越准。
2. **技能与能力**：把你希望被岗位要求对上的能力逐条加进来，标上熟练度。清单**不预置任何维度**，
   从空表开始由你自己生长（解析岗位时模型提出的新能力也会落成维度）。
   这里的每一维度都会与岗位要求里的能力条目对上——「有 5 个岗位要求高并发治理，而我只有一般」
   这类判断，全靠这一步。
3. **项目经验**：写清楚每个项目做了什么、拿到了什么结果，再填它持续了几个月。
   写得越具体，模型判定「是否有 N 年以上相关经验」时越有依据。

> 顶部横幅实时汇总三块资产：知识与能力的熟练度分布、项目数量与累计持续时长。

### 场景二：录入一个目标岗位（岗位信息 → 岗位录入）

1. 点右上角「岗位录入」，选目标分类（没有就点「管理 / 新增分类」建一个）。
2. 把招聘页面上的文字整段粘进去；同一岗位的多段内容之间可以用空行分隔。
   截图可以点击选择、拖拽，或在截完图后直接按 Ctrl+V 粘进来（同一岗位可多张，长 JD 常要两三屏），
   交给支持图像输入的模型解析。
3. **一次只解析一个岗位**：文本与全部截图合成一次请求；解析失败会写明原因，
   原文和截图留在原处，改完可以直接重试。要录下一个岗位，再点一次「岗位录入」。
4. 解析结果进入**待确认列表**：可以改公司名、职位、薪资、城市；每条要求都列出来供核对；
   模型没把握的地方会给出警告（「未提取到知识类要求」「有 2 条能力要求未给出结论」）。
   公司、地区、薪资三项必填——缺了会逐项标红并写明还差哪几项，「确认入库」点不动；
   职位、业务领域与岗位原链接可以留空（链接填了就一定是 http/https 地址，不然会被拒）。
   核对无误才点「确认入库」——系统不会静默保存。
5. 检测到同分类下已有同公司同职位时，提示用户选择「覆盖已有」还是丢弃。

### 场景三：决定先投哪一家（岗位信息 → 列表）

列表按「综合匹配度」降序排好（也可以按已录入天数、最低薪资排，或切升降序）。

每张卡片回答四个问题：**这家给多少**（薪资）、**在哪做什么**（城市 / 业务方向）、
**我差多少**（知识 / 能力 / 经验三个分数 + 综合分）、**差在哪**（未满足的硬性知识直接列出来）。

筛选条在顶部吸顶：关键词、分类、城市、状态各筛选一次，数量由服务端算——
注意**筛选条上的选项不会因为筛选而消失**，选中「北京」之后依然能换回「上海」。

状态就地下拉切换（未投递 / 已投递待回应 / 面试中 / 已发Offer / 已被拒绝），切完立即重排。

### 场景四：搞清楚「我到底差在哪」（深度分析）

点卡片上的「深度分析」或标题，打开抽屉。三类要求逐条摊开：

* **知识要求对比**：结论由**本地精确比对**得出——知识库里没有就是「不匹配」（要红得名副其实：
  这条得从零补），有、但自评等级低于岗位要求就是「需提升」，达到或超过就是「完全匹配」。
  所以它永远和知识库一致，新增一项知识后这里的结论立刻变。
* **能力要求对比 / 经验要求对比**：结论由模型在解析时对照你的技能与能力、项目经验给出，
  每条都带一句依据（「项目经验中有 14 个月的 FastAPI 高并发项目」或「个人资产中未提及相关经历」）。

如果解析之后你改过个人资产，抽屉顶部会出现提示条：**「个人资产已变更，建议重新评估」**。
点一下才会重新调用模型——不点就不会产生任何请求。

### 场景五：知道该补什么（综合看板）

看板把所有岗位聚起来回答「下一步学什么」：

* 顶部四个指标：总关注岗位（含近 10 天新增、超过 20 天未处理）、平均综合匹配度、
  Offer / 总投递转化、待提升项总量（含高优先级项数）。
* 三张环形图：投递状态分布、岗位类型分布、城市分布。颜色与卡片上的状态徽章同一套。
* 匹配度分层统计：六档各有多少岗位、占比多少、典型代表是哪几家（堆叠条一眼看出重心）。
* **待学习知识与待提升能力**：跨岗位统计「有多少个岗位提过它，而我还不会」，
  按提及数分高 / 中 / 低三档；可以只看知识或只看能力。

这些数字全部由本地实时算出，**打开看板不产生任何模型调用**。

### 场景六：拿到该方向的成长路线（岗位信息 → 综合分析）

在筛选条里选中某个分类后，点「综合分析 ·〈分类名〉」：

1. **能力雷达图**：该方向高频要求的六个能力维度上，「岗位平均要求」与「我的当前水平」的差距。
2. **高频缺口**：这个方向所有岗位的缺口排行，带提及数与优先级。
3. **成长路线**：知识学习路线 + 能力提升路径两条，每条 3–5 步，标着优先级
   （高 / 中 / 常规拓展 / 优势巩固），每步都写清楚「为什么补、下一步做什么」。

**第一次打开时是没有路线的**，只有一句说明和一个按钮。点「生成成长路线」才会调用模型，
结果显示在界面上并缓存在本机——以后反复打开都读缓存，不再花钱。
如果生成时你还没录项目经验和技能与能力，界面会明确标注「以下为通用建议」。

### 场景七：换一个模型（系统设置）

设置页分两块：

1. **模型推理参数**：先选**当前模型**（下拉里只有当前厂商的模型），再调它自己的温度
   （默认 0.2，因为这里的调用几乎都是结构化提取，要的是稳定复现而不是发散）。
   **参数跟着模型走**：同一个厂商下换个模型，这套数值就换成那个模型自己的，互不干扰。
   这一栏没有「请求超时」「响应流式输出」这类开关——它们是实现细节，内置在工具里
   （超时按调用路径定死；成长路线本来就是逐字流式呈现，不是二选一），不需要用户操心。
2. **LLM 模型厂商与接口配置**：厂商要自己添加（系统不预置任何一家），添加时可以从预设模板
   一键填入地址与常见模型名，也可以手填（DeepSeek / OpenAI / 阿里 / 月之暗面 / 本地 Ollama / 任意兼容服务）。
   每家有地址、密钥、模型清单与一个「测试连通性」按钮；其中一家是**当前厂商**。
   密钥存进本机配置文件后界面只显示掩码，输入框留空表示「保持原密钥不变」。

**厂商 → 模型 → 参数**逐层跟随：当前厂商决定能选哪些模型，当前模型决定用哪套参数。
解析岗位与生成成长路线都走「当前厂商的当前模型 + 它的参数」。

工具里没有"系统级 Prompt"这类设置项——提示词是工具能力的一部分，内置在代码里，不需要用户去拼。
**其它任何功能都不需要模型；一家厂商都没添加时，除解析岗位与生成成长路线外的功能照常可用**，
而这两处会明确告诉你「尚未配置模型服务商」。
